# Memo 功能清单（v1.6.2，2026-11-11 按代码逐项核对）

一句话：Electron 写的桌面置顶小窗，四个页面（每日常规 / 零碎待办 / 记录 / 想法），所有数据存在本机一个 JSON 文件里，提醒用系统通知。

## 一、总表

「怎么实现」写的是关键机制和代码位置；「测试」= 有没有 `npm test` 里的纯函数用例（✓ 有 / — 没有，靠界面截图测试 `ui-check`）。

## 二、数据长什么样

全部在一个 `config.json` 里，按 key 分：

| key | 存什么 |
|-----|-------|
| `tasks` | 每日常规和零碎待办（`type` 区分），含计时段、计划 / 截止时间、提醒设置、分区 |
| `dailyHistory` | 每天一条：总数、完成数、漏掉的名字、每项明细（计时分钟和时间段），永久保留 |
| `todoLog` | 待办完成日志，清除已完成后也不删 |
| `ideas` | 想法，含状态、分区、来源（剪贴板） |
| `checkTime` / `lastNotifiedDate` / `lastResetDate` | 晚间检查时间、今天提醒过没有、上次重置日期 |
| `view` / `todoSort` / `theme` / `alwaysOnTop` / `windowBounds` | 界面偏好 |

## 三、核对时发现的边界（代码就是这样，不是 bug 报告）

| 现在没有 / 有限制的 | 具体情况 |
|------|------|
| 常规只能「每天」 | 没有「每周一三五」「每周 3 次」这种频率，所有常规每天都算一次 |
| 待办不能重复 | 没有「每周五交周报」这类循环待办，做完就结束 |
| 统计按名字合并 | 每项常规的完成率按名字归类，改名后新旧名字分成两条 |
| 没有搜索、子任务、附件 | 只有分区一种归类方式 |
| 没有导出 / 备份 / 多设备同步 | 数据只在一台电脑的一个文件里，换电脑要手动拷 `config.json`；手机端只能靠微信剪贴板单向收想法 |
| 开机自启关不掉 | 安装版每次启动都重新打开自启，界面里没有开关 |
| 一句话解析是规则，不是模型 | 只认上面列出的说法，一句话里只取第一个时间 |
| 窗口宽度上限 400 | 设计成侧边小窗，不能拉成大窗口 |
| Mac 版没在真机上用过 | 只在 GitHub 的 Mac 打包机上打开自检过 |
